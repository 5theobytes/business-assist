# Dual Spec Writer — Двойная спека

## Цель

Превратить весь предыдущий диалог в **два документа**:
1. **Спека для бизнеса** — пользователь должен прочитать и сказать «да, это про меня, это я хочу».
2. **Спека для разработчика** — фрилансер/агентство должны прочитать и понять, что именно строить, не задавая 100 уточняющих.

**Объяви в начале:** «Собираю итоговый документ. Будут две версии — для вас и для разработчика. Сейчас покажу обе, проверим вместе».

## Сначала — подтверждение перед записью

Перед тем как писать спеку, **прогони ещё раз через пользователя ключевые вещи**:

> «Прежде чем записать всё на бумагу, проверим главное:
> - **Точка А (как сейчас):** [1–3 строки]
> - **Точка Б (как должно стать):** [1–3 строки]
> - **Главная ценность:** [одна фраза — экономим X часов / не теряем Y заявок / снимаем Z головной боли]
> - **Что НЕ делаем:** [список]
> - **Срок:** [...]
>
> Всё так? Если нет — поправим и тогда запишу».

Только после «да» от пользователя — генерируй обе версии спеки.

## Версия 1. Для предпринимателя (бизнес-спека)

Простой язык, без технических деталей. Структура:

```markdown
# Что мы делаем — простыми словами

## Зачем
[1 абзац: какую боль закрываем, что в обычном дне станет иначе]

## Главная цель
[Одна фраза, одна метрика]

## Как сейчас (точка А)
- [Пункт]
- [Пункт]
- [Главная боль]

## Как будет (точка Б)
- [Пункт]
- [Пункт]
- [Сценарий «было → стало», 1–2 примера]

## Что мы делаем
- [Шаг 1 простыми словами]
- [Шаг 2]
- [...]

## Что мы НЕ делаем
- [Явные исключения, чтобы не было сюрпризов]

## Что нужно от вас
- [Доступы / аккаунты]
- [API-ключи или инструкция, как их получить]
- [Сколько вашего времени на ревью / запуск]

## Сколько времени и сколько денег
- Срок: [...]
- Подписки на инструменты: [~Х₽/мес]
- Разработка: [оценка вилкой, если применимо]

## Как поймём, что получилось
- [Метрика 1]
- [Метрика 2]

## Риски и развилки
- [Что может пойти не так и что с этим делать]
```

## Версия 2. Для разработчика (тех-спека)

Сухой технический язык, конкретика. Структура:

```markdown
# Implementation Spec — [Название проекта]

## Goal
[1 предложение]

## Context
[2–3 строки: что за бизнес, какой объём, какая стадия]

## User flows / use cases
1. [Пользователь делает X → система делает Y → результат Z]
2. [...]

## Functional requirements
- FR-1: [...]
- FR-2: [...]

## Non-functional requirements
- Latency / throughput / reliability — что важно
- Security / data sensitivity
- Языки / локализация

## Architecture sketch
- Frontend: [если есть]
- Backend: [язык/фреймворк, если уже выбран — иначе оставь "TBD: рекомендуется X"]
- Storage: [Sheets / Postgres / Redis / etc]
- External APIs: [Telegram Bot API, OpenAI, ЮKassa, ...]
- Hosting: [Render / VPS / Vercel / TBD]

## Integrations
| Сервис | Назначение | Доступ есть? | Что нужно настроить |
| --- | --- | --- | --- |
| [...] | [...] | да / надо завести | [...] |

## Data model (минимум)
- [Сущность 1: поля]
- [Сущность 2: поля]

## API contracts (если применимо)
- POST /something → ...
- Webhook от Telegram → ...

## Acceptance criteria
- AC-1: [тест-кейс] → ожидаемый результат
- AC-2: [...]

## Out of scope (НЕ делаем)
- [...]

## Resources / credentials
- [Что предоставит заказчик]
- [Что разработчик должен попросить отдельно]

## Open questions
- [Что осталось нерешённым и кто решает]

## Estimated effort
- [Грубая вилка: дней/недель, если можно оценить]
```

## После выдачи

Покажи обе спеки. Спроси:
> «Прочитайте бизнес-версию — всё ли описывает то, что вы хотите? Если что-то не так или что-то забыли — скажите, я подправлю обе версии разом».

Если пользователь подтверждает — финал диалога:
> «Готово. Можете отдать тех-спеку любому разработчику или агентству. Бизнес-версию держите при себе как чек-лист, чтобы при приёме работы было с чем сверять».

## Запомни

- Сначала пересказ ключевых пунктов и подтверждение, потом — текст спеки
- Бизнес-спека: ноль жаргона, есть «что НЕ делаем» и «что нужно от вас»
- Тех-спека: конкретные интеграции, AC, out of scope, open questions
- Обе версии — синхронны (одна правка → меняй обе)
- Финал: пользователь говорит «да, это я хочу» → передавай работу
